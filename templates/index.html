02 / INTEGRATION

GeoJSON for Leaflet and Google Maps.

Leaflet

A boundary overlay on your chosen base map. The runnable example uses Leaflet 1.9.4 and OpenStreetMap.

const response = await fetch('./data/active.geojson');
if (!response.ok) throw new Error(response.status);
const zones = await response.json();
const layer = L.geoJSON(zones).addTo(map);
if (layer.getBounds().isValid()) {
  map.fitBounds(layer.getBounds());
}
Run the Leaflet example →

Google Maps

The Google Maps Data layer loads the same GeoJSON. Running the example requires your own Maps JavaScript API key.

const response = await fetch('./data/active.geojson');
if (!response.ok) throw new Error(response.status);
const zones = await response.json();
map.data.addGeoJson(zones);
map.data.setStyle({
  fillColor: '#19754a', fillOpacity: 0.18,
  strokeColor: '#19754a', strokeWeight: 2
});
Run the Google Maps example →

Helper functions

The assets/zones.js module handles data loading, filtering by country and status, styling, popups and fitting map bounds. Load Leaflet or Google Maps separately.

import { loadZones, addLeafletZones, addGoogleZones } from './assets/zones.js';
const data = await loadZones('./data/zones.geojson');
const leafletLayer = addLeafletZones(L, map, data, { country: 'DE' });
// Alternatively, in a Google Maps application:
const googleLayer = addGoogleZones(google, googleMap, data, { status: 'active' });

The default status is active. Set status: 'all' to include historical records. Use fitBounds: false to retain the current viewport. The Leaflet helper returns L.GeoJSON; the Google helper returns an independent google.maps.Data layer. Remove them with map.removeLayer(layer) or layer.setMap(null), respectively.

Do not reverse GeoJSON coordinates: both libraries handle their native order. Public OSM tiles have a separate usage policy; choose an appropriate tile provider for production.

04 / FORMAT

Readable data with traceable provenance.

PropertyMeaning
id, name, country, regionRecord identity, source name and geographic classification
typelow_emission_zone; currently German Umweltzonen only
statusactive / abolished; the format also permits planned / unknown
valid_from, valid_toSource first-stage date and effective abolition date; unknown dates are null
retrieved_at, verified_atRetrieval and independent verification times; verified_at is currently null
status_basis, geometry_accuracysource_snapshot and schematic describe the scope of the data
sourcePublisher, source ID, URL, licence and attribution
source_attributesOriginal UBA attributes, including status codes and stage dates

valid_to is the effective abolition date. IDs do not change when statuses change. The dataset does not provide complete rules for fuels, emission classes, time-based exemptions or individual streets, and cannot independently determine whether a vehicle may enter a zone.

05 / SOURCES AND UPDATES

Every geometry retains its source.

German data comes from the UBA polygon layer. It includes active and abolished zones. Records are filtered by the status attribute, not the layer name.

Geodata licence: GeoNutzV, as stated in the service metadata. Attribution: © Umweltbundesamt (UBA); modified: conversion to WGS84/GeoJSON and attribute normalization. Project code is MIT-licensed; this does not relicense source geodata.

Updates are manual: run npm run update:uba, then npm run build, review the changes and run npm test. Downloading a snapshot does not independently verify current legal rules. GitHub Actions checks data and publishes the documentation when the main branch changes.
